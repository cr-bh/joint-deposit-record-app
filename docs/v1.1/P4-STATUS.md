## P4 交付与证据

| 要求 / 验收 | 结果 |
|---|---|
| 同一成员、一个付款账户/币种，选择原单部分/合并报销 | 专用表单/API/RPC；重复原单先合并，跨成员/无来源/超额/非法整数拒绝 |
| AC-15 原单300报销100 | PostgreSQL 现金记录100、原币剩余200、状态部分结清 |
| AC-16 CNY360 + HKD780 → USD150 | 锁7.2/7.8快照，原币预留360/780，批准扣USD150；CNY剩360/HKD结清；后来7.5下剩360新付USD48，旧USD150不变 |
| AC-17 两个80争100额度 | 两个独立 SQL 连接并发调用：一个成功、一个额度不足，剩可用20；全批次回滚无部分预留 |
| AC-18 撤回/驳回/逾期 | 提交者撤回、另一成员驳回释放；重复撤回/驳回幂等；逾期待审保留；批准与撤回竞争只能一个终态 |
| AC-19 分摊守恒 | BigInt/SQL整数有理数，总额仅半入舍入一次，先向下取分再按尾差降序、稳定原单键分配；3×CNY1→USD0.42各0.14；3×CNY0.10→USD0.04分配0.02/0.01/0.01 |
| 零分拒绝 | 总额不足一分及单笔分摊为零均整体拒绝，包括USD1+CNY0.01场景；不核销零分原单 |
| AC-20 / 权限 | 跨成员、跨账本/非成员、无原单与旧自由金额 settlement 入口被拒绝；成员可读、外部用户RLS不可读、直接DML不可写 |
| 审批事务 / 重试 | 批准同事务写现金、转换预留为正式核销、更新原单状态/审计；两个会话重复批准只有一次现金事件；失败不留半写入 |
| 依赖版本 | `expectedVersion` 保存到分配；批准复查原单状态、来源、版本、成员与总已核销/预留；失效则保留待审供撤回，不偷偷重算 |
| 汇率精度 | 带RLS的 security-invoker 文本汇率视图保留10位小数；锁定批准快照，核销算法不使用浮点中间乘积 |
| PR-08 界面 | 代付/打款子页、原单↔批次、待审代付/未结清/预留子集/已付原币卡片、币种堆叠进度、原单时间线、审批原币分配和批准后余额 |
| 已付/未付口径 | 实际打款按付款币种；原单核销/未结清/预留按债权原币；批准打款不新增共同消费，也不拆费用 |
| P3 已关联历史打款升级 | 仅显式收款人、同币种、同账本、完整分配且分配总额等于现金流水的旧打款转换为批次；金额不改、已核销不丢、剩余额度正确。其他历史打款显示待核对，不猜测 |

原单 `version` 是来源债务的修订号；单纯预留或打款不推进它，避免同一原单多个合法预留互相失效。未来 P6 退款/更正必须推进该版本，并处理现存预留。原币余额在 P4 为原额减有效核销，P6 应按 PRD 加入退款与应返款公式。
