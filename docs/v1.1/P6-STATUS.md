## P6交付与证据

| 范围 | 最终行为与验证 |
|---|---|
| 原消费退款 | 从消费/代付原单发起，服务端继承原币/类别/事项，累计有效退款不超过原额；并发两个80/原100仅一个批准。共同消费只能退共同账户；代付可退原垫付成员或共同账户。旧任意退款入口禁止绕过。 |
| 去向与债权 | 个人退款减少消费及可报销额，共同现金不变；直接退共同账户减少消费、增加指定现金，原垫款欠款不重复减少。G原额、F个人退款、S核销、T已返：A=G−F，L=max(A−S,0)，U=max(S−A,0)−T；不抵销其他原单/成员。 |
| 返还 | AC25 G300/S300/F100形成U100，返还100后U0；AC63 G300/S100/F250形成U50、L0。待审/逾期预留返还原币，两真实会话争抢80%额度仅一个成功，撤回/驳回释放。重复批准只入账一次。CNY360原款到账USD50，金额与已批准汇率快照保留，返还不计消费或贡献。 |
| 报销预留 | AC64 原100已预留80，个人退款50不能批准且无半笔退款；先撤回打款后才能退款，随后普通打款按有效额度预留。退款改变原单版本，过期待审款需撤回重提。 |
| 双人作废 | 原因必填、不能自批，原流水/原审批保留，作废申请冻结影响并写审计；统计排除作废项，不插反向现金。审批显示各账户/币种现金前后金额、持仓/成本/已实现收益/分红及原单未清/应返前后数值，批准重查变化。 |
| 打款和组合 | 打款整批核销一并作废，恢复每笔原币欠款；转账/换汇双边、银行转入+买入按原提案全组撤销。CNY720→USD95、买100作废后CNY现金+720、券商USD+5、股数归零。负现金合法，不自动补差。 |
| 依赖与回滚 | 原单有效退款/核销/预留、已返/待审返还阻止破坏性上游作废。后续卖出造成负持仓或外部买入引用转入则阻止。估值基准失效需先作废确认估值/撤回待审估值。作废第二步故障后买入、转入、提案状态和批准审计全部回滚，重试成功。 |
| 替代提案 | 常规存入/消费/代付/划转/换汇/买卖/分红可在作废批准后另建关联待审记录，作者保持原申请人，另一方单独批准。前端改说明和实际金额，其他事实沿用。退款/返还/报销/汇率/估值从原入口重提；当前不提供多记录原子替换流程，不自动批准替代记录。 |
| 历史和追溯 | 流水保留作废标记/审批锚点；退款、代付可定向打开原消费并返回完整流水。原单展示原额、个人退款、有效原额、核销、应返总额、已返、尚需返还、返还预留及可返还，状态明确“需返还共同款”。打款批次与估值历史有作废入口；作废估值回退有效旧价或成本暂估。 |
| 权限与升级 | 12份迁移在干净PostgreSQL执行，原P3→P4/P4→P5升级仍通过；作废申请RLS隔离、直接DML和私有RPC拒绝。旧已入账无来源退款保留待P8盘点，不猜关联；旧待审无来源退款须撤回后按原单重提。 |
