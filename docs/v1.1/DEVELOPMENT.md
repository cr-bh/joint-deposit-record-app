## 本次工作包

P0 基线资料＋PR-01 的第一批领域及页面修复。P0、PR-01、P1 均未整期验收完成。原界面结构继续沿用，无新设计体系。

已实现：

- 投资按发生日及稳定键重放，和页面倒序无关；遇到超卖、缺数量、非法整数抛出错误，投资卡片显示待核对，不静默跳过。
- 同一领域函数用于持仓与投资卡片；结转成本用整数比例计算，避免中间乘积浮点误差，清仓成本为零。金额仍取交易实际金额。
- 总览复用领域现金影响规则，按 USD/CNY/HKD 汇总。没有已确认汇率则折算值为空并显示提示，原币与负现金保留。
- 消费趋势按日期正序，保留负退款；涉及缺失汇率时不显示假折算趋势。
- 同日估值按 value_date、created_at、id 稳定选择；未录估值显示成本暂估和“待估值”，不再显示零市值及虚假亏损。
- 在线行通过类型校验后转领域对象，删除投资页面 `as never` 强制转换。历史 member_id 仅作为 submitter，不推断实际垫付人。
- 成员计算接受真实 UUID、显式 payer/payee，删除固定演示姓名过滤。该旧汇总函数尚不构成 P3/P4 债权及核销实现，不在在线页面展示未经核对的历史欠款。
- proposal 批准终态统一为 approved，流水仍为 posted。
- 分红、买卖、估值表单币种统一取投资标的，避免外币分红误用报告币种。
- 账本查询出错进入可重试错误页，不再将读失败当作空账本/零余额。
- 新增仅开发环境可访问的 `/preview` 只读页面，以合成数据展示总览、审批、流水和投资；没有 Supabase 配置时也可检查当前界面和领域计算结果。
- 提案 API 改为按类型严格校验，并将非法 JSON 或字段组合稳定返回 400；费用类别、投资引用、数量、估值价格及零到账卖出分别遵守对应规则。
- Next.js 请求边界由已弃用的 `middleware` 文件约定迁移为 `proxy`，保留认证逻辑及开发预览例外。
- 买卖表单将实际总扣款/净到账与可选参考价分开；金额和份额由十进制文本直接换算为整数，避免浮点舍入，参考价不再决定入账金额。
- 同一表单草稿固定幂等键，提交期间禁用字段和按钮；网络或服务端失败保留草稿及原幂等键供重试。
- 新增 P1 增量迁移：数据库按类型复验 payload、拒绝跨账本标的和未来入账，锁账本/标的、分配稳定序号，并让重复提交或重复批准返回原结果。
- 增量迁移补回驳回审计、成员资料互读策略及 payer/payee 明确列；这些字段的完整表单与债权链路仍属于后续 P3/P4 工作。
- 审批 API 对非法 JSON、非法提案 UUID 和多余字段统一返回 400；决定必须是布尔值，非空备注会裁剪并限制为 500 字。
- 投资交易参考价与人工估值统一以 1e4 定点整数写入、读取和计算；旧 minor 字段保留为四舍五入兼容镜像，旧待审批 payload 与旧价格 RPC 会转接到新精度模型。
- 移除投资卡片和 API 的人工直接改价入口；估值与买卖、分红一样，从对应标的的“投资操作”表单提交并经另一人批准，数据库迁移删除旧直接写价 RPC。
- 个人存入和成员代付必须从活跃账本成员中明确选择实际付款人，默认当前用户但允许选择另一人；提交、数据库复验、批准入账、审批卡片和流水展示已贯通，提交者不再被当成付款事实。
- 消费、存入、代付和报销由页头“新建账本记录”触发；每张投资卡片提供绑定该标的的“投资操作”，包含买入、卖出、分红和估值。两类入口复用同一提案 API、幂等与双人审批链路。
- 服务端以 500 条一页读取完整流水、审批、标的、估值和成员数据，在服务端计算总览及投资持仓；浏览器仅接收最近 100 条流水用于列表展示，统计结果不再受 Supabase 默认 1000 条上限影响。
- 账本相关表写入会推进 `households.ledger_version`；服务端读取前后核对版本，发现并发写入时整批重读，连续三次变化则明确提示重试，避免一次页面响应混用不同时点的数据。
- 邀请创建与接受统一锁定账本行后检查活跃状态和两人上限，避免两份邀请并发接受成为第三人；邀请 API 拒绝非法 JSON、路径 ID、多余字段和非法令牌，并将失效、邮箱不匹配等数据库状态转换为中文提示。
- 未登录访问受保护页会通过安全的站内 `next` 参数经过登录、注册和邮箱验证后回到原路径；外部 URL、协议相对路径及反斜线路径会回退首页，邀请路径不再在认证过程中丢失。
- P1 迁移会把旧库中位于 `public` 的 `pgcrypto` 移到 `extensions` 后再统一使用限定函数名，兼容新旧初始化顺序。
- P2 PR-03 首个纵向切片已建立共同银行与共同券商两类现金账户。普通存入、消费和报销付款可明确选择账户并默认共同银行；买卖与分红固定结算到共同券商，成员代付不改变共同账户现金。
- 同币种银行/券商内部划转通过独立提案审批，并在一次数据库事务中写入同时包含转出与转入账户的不可拆分划转记录；领域核算将其展开为等额正负两端，所以共同现金与贡献不变。
- 总览按 USD/CNY/HKD 分别展示两类账户现金，保留负余额；流水显示普通记录的入账账户及内部划转方向。计算不会因账户为负而自动补差、自动转账或自动换汇。
- P2 增量迁移为旧流水按互斥规则回填账户：投资买卖/分红归共同券商，成员代付不归共同现金，其余旧现金事件归共同银行；同一事件不会同时走旧汇总与新增现金明细两套计数。
- P2 PR-04 已实现经双人审批生效的手动 USD 基准汇率完整快照，同时保存 USD/CNY、USD/HKD、有效时间、人工来源、提交者与批准者。待审批快照不参与正式总览，超过 24 小时只提示，不自动停用，也不抓取或伪装实时行情。
- 当前现金按最新已批准快照折算；外币消费流水保存 `fx_snapshot_id`，历史趋势按各自锁定快照折算。更新 CNY 汇率只改变当前资产折算，不改原币现金或已确认历史消费。
- 新增“实际换汇”账户记录，可在同一或不同账户间保存来源币实际总扣款与目标币实际净到账。两端在一个不可拆分的划转对象中生效，换汇不计共同存入、普通消费或投资收益，也不另行推断已包含的费用。
- 总览显示最新确认汇率的明确方向与来源；审批中心展示整组待审快照，流水同时展示换汇两端实际金额。开发预览包含已批准 7.2/7.8、待审批 7.5/7.85 和 100 USD→780 HKD 合成场景。
