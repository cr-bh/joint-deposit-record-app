## 邮件失败处理

三种凭据用途不同：

| 位置 | 使用的凭据 |
|---|---|
| Supabase SMTP Username / Sender email | 生成应用密码的同一个Gmail账号 |
| Supabase SMTP Password | 从[Google应用密码页面](https://myaccount.google.com/apppasswords)生成的16位应用密码；不是普通Gmail密码 |
| 共筑注册 / 登录 Password | 用户在共筑注册时自行设置的账号密码；不需要填SMTP应用密码 |

注册邮件发送失败时不要改用发信Gmail账号直接登录；须先完成该邮箱的共筑注册和邮箱确认。

- 确认邮件检查垃圾邮件；不要连续反复提交，页面重发按钮有60秒间隔。
- 登录显示邮箱未验证：在注册浏览器打开有效邮件链接；失效可请求重发。
- 仍无法发送：检查Supabase Auth日志与Gmail SMTP配置。Sender email与Username使用同一个Gmail地址；Password为应用密码而非Gmail登录密码，不写进 `.env.local`。
- Gmail应用密码需要两步验证；账号策略可能禁止生成，修改Google账号密码后应用密码可能失效。参考[Google说明](https://support.google.com/accounts/answer/185833)和[Supabase配置说明](https://supabase.com/docs/guides/troubleshooting/using-google-smtp-with-supabase-custom-smtp-ZZzU4Y)。不要关闭邮箱确认来替代送达验收。
